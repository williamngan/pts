# Review of the unreleased 1.x fixes

October 12, 2026. Scope: the 28 local commits `origin/master..6a7133b`
(`bd368e2` … `6a7133b`), compared with the published 1.0.2 (`f6ca88c`).

## Verdict

The fixes are mostly sound and well tested, but four commits regress
performance or robustness in ways the tests do not cover. Fix those before
releasing:

1. `55f58ab`: every CanvasForm style call now reads the context back.
2. `661acc7`: Path sweep pruning makes another common layout quadratic.
3. `ea29b7f`: one lost press disables drag and drop for good.
4. `d96d1bb`: stopping a microphone while the AudioContext is suspended
   leaves the microphone live.

Several intended behavior changes, notably D50 Lab/LCH, also need release
notes and probably a minor version (see "Behavior changes").

## What was run

- `CI=true pnpm check`: passed, 785 tests (node, visual and browser projects).
  Rebuilding produced no diff, so the committed `dist/`, `docs/` and editor
  artifacts match the source.
- Base and head A/B runs, both builds loaded in one process (Node) or one
  browser (Chromium). The base is `npm pack` of `origin/master`; the head is
  `npm pack` of `6a7133b`.
- react-pts-canvas `master` at `3c7917f` (1.0.4), run against both tarballs.
- pts-render `main` at `3085cba` (0.1.1), run against both tarballs: 59 render
  cases diffed (PNG and SVG) and timed.

## Regressions

### 1. CanvasForm style read-back costs 25–50% per frame (`55f58ab`)

`_set()` now reads `ctx[key]` on every call, including cache hits, and builds
an `actual:${key}` string each time. `dash()` calls `getLineDash()` twice.
Chromium getters serialize colors, so the cache-hit path is no longer cheap.

Chromium, `pts.js`, one CanvasForm on a raw 2D context, 3000 shapes per frame:

| Case                                    | base    | head    | ratio |
| --------------------------------------- | ------- | ------- | ----- |
| same `fill`/`stroke` + circle           | 2.94 ms | 3.67 ms | 1.25  |
| alternating fill + rect                 | 1.67 ms | 2.54 ms | 1.52  |
| `dash` toggle + line                    | 1.74 ms | 2.55 ms | 1.47  |
| style setters only (30,000 calls/frame) | 0.12 ms | 2.22 ms | 18    |

The pts-render check (skia-canvas) agrees. `fill()` with an unchanged color
went from 5 ns to 101 ns and `dash()` from 48 ns to 502 ns. Multi-frame PNG
renders are 21–31% slower (20k shapes × 31 frames: 920 → 1208 ms). The
react-pts-canvas check measured 7–28% on its own draw loops.

The correctness gain is real: direct `ctx` writes, `save()`/`restore()` and
`setLineDash()` are no longer hidden by the cache. But it is paid on every
style call of every sketch. Options that keep most of the fix:

- Invalidate the cache when `form.ctx` is read. That is the documented way to
  reach the context, so direct writes and save/restore through it are caught,
  at no per-call cost.
- Otherwise, revalidate once per frame (at `playItems` start), not per call.
- If per-call checks stay: precompute the `actual:` keys, and skip the second
  `getLineDash()` when `dash()` wrote nothing.

### 2. Path sweep: the transposed layout becomes quadratic (`661acc7`)

The new interval hierarchy keeps its leaves in y order, so its x pruning
(`left[n] > limit`) only works when y order matches x order. When boxes are
disjoint in x but overlap in y with varied tops, nothing is pruned and every
edge walks most of the tree. The old x sweep handled that case with an early
`break`. The added benchmark covers only full-width bars, which is the case
being fixed.

`Path.unite`, best of 3, Node:

| Input                                      | base     | head     | ratio    |
| ------------------------------------------ | -------- | -------- | -------- |
| 2000 full-width bars (the fixed case)      | 53–60 ms | 13–23 ms | 0.25–0.4 |
| 2000 tall bars side by side, tops jittered | 15 ms    | 85 ms    | 5.3      |
| 4000 tall bars, tops jittered              | 40 ms    | 323 ms   | 8.0      |
| 8000 tall bars, tops jittered              | 113 ms   | 1326 ms  | 11.7     |
| 3000 random small squares                  | 28 ms    | 43 ms    | 1.5      |
| one 20,000-gon                             | 9–10 ms  | 15–18 ms | 1.4–2.1  |
| zigzag comb, 5000 teeth                    | 3.4 ms   | 5.2 ms   | 1.5      |
| 2000 full-height bars (y order = x order)  | 5–7 ms   | 7 ms     | ~1.1     |

Repro input: `Array.from({length: n}, (_, i) => { const y = rnd() * 500;
return [[i*3, y], [i*3+1, y], [i*3+1, y+1000], [i*3, y+1000]]; })`.

Suggested fix: build the hierarchy over the existing x order (leaves = `order`
positions, nodes holding min `minY` and max `maxY`). For edge `i`, find the
last `j` with `minX[order[j]] <= limit` by binary search, then query only
`(i, j]` and prune by y. This keeps the old x cutoff, adds y pruning for the
full-width case, and traverses in order, so candidates need no sort. Add the
tall-bar and random-square cases to `bench/suites/op.bench.mjs` next to the
full-width bars.

### 3. One lost press disables drag and drop (`ea29b7f`)

`_pressed`/`_pressId` are now released only by an event from the owning
contact. A pointer-event press is never released by a TouchEvent or a different
`pointerId`, and `bindMouse(false)`/`bindTouch(false)` do not clear it. If the
owner's up is lost, every later gesture is reported as `move`/`up` instead of
`drag`/`drop`, permanently. A mouse press cannot take ownership while the
stale press exists. Before, any `pointerup`, `pointerout` or `click` reset the
press, so the state healed itself.

Repro (headless `MultiTouchSpace` as in `src/test/Space.spec.ts`):
`pointerdown` with `pointerId: 7`, then `bindMouse(false); bindMouse(true)`,
then a mouse gesture with `pointerId: 1` gives
`down,pointerdown,move,pointerup,up`. Without the first press it gives
`down,pointerdown,drag,pointerup,drop`.

The react-pts-canvas check reproduced it in Chromium with real touch
emulation: start a touch, rerender with `input={{pointer: true, touch: false}}`,
end the touch. After that, every mouse drag lost `drag`/`drop` until touch was
re-enabled and tapped.

Suggested fix: clear the press in `bindMouse(false)`/`bindTouch(false)` and on
`lostpointercapture`. Also let a new press take over when the stale owner can
no longer deliver an up: a pointer press while a touch owns it, or a
`touchstart` with `touches.length === changedTouches.length`.

### 4. Stopping a microphone while the context is suspended keeps it live (`d96d1bb`)

`stop()` on an input now defers `track.stop()` through `_afterFade`, which
waits for `ctx.currentTime` to pass the fade end. A suspended context's clock
does not advance, so the tracks stay live and the timer re-arms every 10 ms
until the context resumes. Before, `stop()` ended the tracks immediately.

Chromium with a fake microphone: `Sound.input()`, `start()`, `ctx.suspend()`,
`stop()`, wait 500 ms. Track `readyState`: base `"ended"`, head `"live"`. It
switches to `"ended"` only after `ctx.resume()`. The browser's recording
indicator stays on, which is a privacy-visible regression. The same polling
affects media-element and custom-node stops.

Suggested fix: in `_afterFade`, finish immediately when
`ctx.state !== "running"`. For inputs, stop the tracks at once after the gain
ramp is scheduled.

### 5. SVG: one element per filled or translucent shape (`3a62679`)

The rendering is now correct (fills and translucent strokes composite like
canvas), but the cost is larger than the changelog suggests. SVGSpace,
Chromium, median frame time including `commitFrame` and layout:

| Scene                     | base frame | head frame | elements  | markup bytes  |
| ------------------------- | ---------- | ---------- | --------- | ------------- |
| 1000 filled circles       | 0.6 ms     | 2.0 ms     | 3 → 1002  | 45 K → 121 K  |
| 5000 fill+stroke circles  | 2.8 ms     | 8.8 ms     | 3 → 5002  | 226 K → 921 K |
| 20000 filled circles      | 8.3 ms     | 29.7 ms    | 3 → 20002 | 0.9 M → 2.4 M |
| 20000 translucent strokes | 6.6 ms     | 29.2 ms    | 3 → 20002 | 0.3 M → 3.3 M |

At 20,000 shapes the frame rate drops from 60 to 30 fps (20 fps with
fill+stroke). Possible narrower rules:

- Treat `rgb()`, `hsl()` and named colors without alpha as opaque. Today only
  `#hex` strokes qualify.
- Merge fill-only, opaque, same-color runs whose subpaths all wind the same way.
  Pts' own primitives do, and same-winding overlaps fill identically under
  `nonzero`.
- Otherwise, state the per-shape element cost in the guide and the changelog.

pts-render is unaffected: it uses skia-canvas's SVG encoder, not
`SVGContext2D`.

### 6. Exact predicates in the hot path and in every CanvasSpace bundle (`15ca003`, `bd368e2`)

`Line.intersectLine2D` now runs three exact `orient2d` calls before the
ordinary intersection, on every call. On 400,000 random segment pairs it is
23% slower (32.1 → 39.3 ms). Importing `orient2d` from `_triangulate` also
pulls the exact-arithmetic tiers, including the BigInt fallback, into any
bundle that reaches `Line`.

A Vite-minified `import { CanvasSpace }` grew by 5.3 KB (+5.2%) and
`import { Line }` by 3.6 KB (+6.8%). The size ceilings in
`check-package.mjs`/`check-artifacts.mjs` were raised to absorb this, rather
than the growth being traced.

Suggested fix: run the collinear branch only when the ordinary intersection
reports parallel lines (zero denominator). Consider a small standalone exact
`orient2d` (fast filter plus a two-product expansion) so `Op` does not depend
on the triangulation's BigInt tier. `convexHull` is 19% slower too, which is
acceptable given base threw on duplicates, collinear points and tied x.

### 7. Repainting stopped spaces on resize runs animate twice (`8bf7def`)

This is intended and fixes blank canvases after container resizes (verified in
the react-pts-canvas gallery). Side effects worth a changelog line:

- `playOnce(0)` renders synchronously at time 0, then once more at the next
  frame. A stopped or paused sketch now advances two animate steps per observer
  resize.
- A stopped space with a Tempo fires a beat callback on resize.
- For one frame `isPlaying` is true, so pointer moves reach `action`.
  react-pts-canvas documents that `play={false}` suspends `onAction`;
  resizing every frame while stopped delivered 29 of 30 moves.

This was already true for window `resize` events (`evt` set). Now it also
applies to ResizeObserver resizes, which are far more frequent. Consider a
repaint path that calls `playItems` without starting the loop or delivering
input. Otherwise, react-pts-canvas should soften its docs.

## Behavior changes to call out

These are intended, but existing sketches change. Together they look more
like 1.1.0 than 1.0.3. The changelog lists them as fixes, not behavior
changes.

- **Lab/LCH are now D50** (`ee530ce`). This matches CSS: red is
  `lab(54.293 80.807 69.889)`, and blue matches `lab(29.567 68.289 -112.031)`.
  But every existing Lab/LCH color renders differently: `Color.lab(50, 20, 30)`
  went from rgb 164,105,69 to 161,105,69, and pts-render saw `lab(40,20,-60)`
  go from `#135ac2` to `#4356c2`.
- **Tempo counts jump after stalls** (`c0f3fcd`). A tab switch can move `count`
  from 2 to 10. A listener that ends itself with `return count === 3` is never
  removed if the stall skips 3 (base removed it after 4 calls; head is still
  listening after 6). The guide's own example uses `count > 5`, which is
  robust.
- **HSL/HSB → RGB rounds** (`9dd1d9c`). RGB → HSL → RGB is now exact, but
  HSL → RGB → HSL is lossy: `hsl(268, .37, .51)` returns as `268.043, .368`.
  1000 fine lightness steps collapse to 7 RGB values. LAB/LUV → RGB already
  returned integers, so this is at least consistent.
- **`Circle.intersectCircle2D`** returns `[]` for enclosed circles (`9a6a24e`).
  It used to return one circle's center, and code may have used
  `length > 0` as an overlap test. pts-render's compatibility demo lost a dot.
- **`Line.intersectLine2D`** returns a point for collinear overlaps and for a
  zero-length segment lying on the other segment (`15ca003`). So
  `Polygon.intersectPolygon2D` on two squares sharing an edge now returns 7
  points instead of 6.
- **Sound** fades for 10 ms on every start, stop, seek and volume change
  (`d96d1bb`). This softens percussive attacks, delays `pause()` and track
  shutdown by about 10 ms, and `volume` set while stopped no longer writes
  `gain.value`.
- **Input** (`ea29b7f`): touch now emits `pointerdown` as well as `down`. A
  `click` no longer ends a press. The second change is not in the changelog.
  Synthetic events without a matching `pointerId` (as the smoke script had to
  learn) no longer end a press.

## Gaps

- **Voronoi near-duplicates** (`c0db1e7`, withdrawn in the fix pass). A 6×6
  grid rotated by 0.37 rad still gives edges shorter than 1e-3 after the
  exact-equality deduplication. Those sites are not exactly cocircular once
  rounded, so the short edges are real; only exact duplicates are degenerate.
- **Unverified:** `Sound.reset()` calls `stop()` on retiring nodes, which may
  already have ended. The code's own comment says Safari throws
  `InvalidStateError` for that. A `try`/`catch` would be cheap insurance.

## Downstream libraries

**react-pts-canvas** (`master`, 1.0.4, pins pts 1.0.2): lint, typecheck,
27/27 tests, build, docs, package checks and the gallery build and smoke test
all pass on the head build. Probes found:

- the stuck press (regression 3)
- the resize side effects (item 7), including `onAction` during `play={false}`
- the input sequence changes listed above
- style cost of 7–28% at gallery scale

StrictMode, unmounting during a pending `playOnce` and `play` toggling all
behave correctly. The wrapper never calls `resize` or `playOnce` itself.

**pts-render** (`main`, 0.1.1, pins pts 1.0.0): all gate steps pass on the head
build once its harness stops hard-coding `"1.0.0"`. Three checks
(`test/render-scene.test.ts:56`, `scripts/test-cli.mjs:583`,
`scripts/test-compatibility.mjs`) fail for any 1.0.x, independent of these
commits, and `test:pack` always installs pts from npm.

52 of 59 render cases are byte-identical. The other seven come from intended
fixes: the enclosed-circle dot, HSL rounding (max channel delta 3), Lab/LCH,
geometry, Tempo with `--fps 1`, physics with `iterations=4`, and stale styles
that are now correct. The only regression is the style read-back cost
(regression 1). pts-render never uses `SVGContext2D`, `SVGForm`, `SVGSpace`
or `Sound`, and its headless Space bypasses the new press ownership.

## Verified fixes

- Convex hull: base threw on duplicates, collinear input and tied x (including
  20,000 random points with ties), and returned a wrong hull when
  `sorted = true` was passed with unsorted input. Head is correct.
- D50 Lab/LCH values match CSS Color 4 to three decimals. RGB → Lab → RGB is
  exact.
- `Num.boundValue` handles reversed endpoints (`(5, 10, 0)`: 15 → 5), equal
  endpoints and tiny negative values. Its speed is unchanged.
- Hex output clamps (`rgb(300, -5, NaN)`: `#12c-5NaN` → `#ff0000`).
- `Geom.boundingBox([])` and `sortEdges` of fewer than two points are handled.
- Physics: one solver iteration is identical. With four iterations a soft hexagon
  keeps its rest edge length (39.98 → 40.00), with no instability.
- `Pt.subarray` returns a shared view.

## Not tested

Firefox and Safari (including the `cancelAndHoldAtTime` fallback in
`_rampVolume`), real touch hardware, React 18, and GPU rendering in
pts-render. The Path fuzzer passed on seeds 1, 7, 42 and 2026 (2000 trials
each), so `661acc7` is correct; only its speed regressed.

## Fix pass

October 12, 2026. Each fix is measured against 1.0.2 (`f6ca88c`) and the
reviewed head (`6a7133b`). Node figures are paired A/B runs with each build's
code compiled separately (31 alternating 20 ms batches, median ratio; the noise
floor is about ±2%). Chromium figures are per-frame medians. Ratios are new
build / 1.0.2.

### Regressions from the review

1. **Style cache** (`55f58ab`). CanvasForm no longer reads the context back.
   The first time a form draws on a context, it observes the context: own
   accessors over the inherited style setters, and wrappers over
   `setLineDash`, `save`, `restore` and `reset`. A write made through any
   reference to the context then updates the cache, `save()` snapshots it and
   `restore()` reverts it, so a cache hit is one comparison again. The
   observers are built once per context prototype and shared, and the cache is
   linked from the context under a symbol. A context Pts cannot observe
   (frozen, with its own style members, or without style setters) is not
   cached: every style call writes, so no write can leave the cache stale.
   SVGContext2D keeps plain getter/setter pairs over its style fields and is
   observed like a canvas context, without a special hook.

   The first version of this fix (October 12) made the observers per context.
   Each observed context then got its own V8 hidden class, so shared call
   sites in Pts and inside skia-canvas went megamorphic once several contexts
   existed. The single-canvas benchmark missed it. With 8 canvases on a page,
   frames were 1.2–1.37× those of 1.0.2, and skia-canvas drawing 1.05–1.11×.
   Two simpler alternatives were measured and rejected. Forgetting the cache
   whenever `form.ctx` is read is fast, but code holding its own reference to
   the context can draw a stale color. Dropping the cache is exact and at
   parity in Chromium, which skips identical style writes itself, but
   skia-canvas does not: per-shape style loops ran 1.4× slower and repeated
   identical styles 14×.

   Chromium figures below come from one page with one same-origin iframe per
   build, so all builds share a thread and alternate (21 rounds; 41 for the
   `save`/`restore` rows). Separate pages were too noisy for these cases.

   | Chromium, 3000 shapes per frame       | 1.0.2   | first fix | new       |
   | ------------------------------------- | ------- | --------- | --------- |
   | same style + circle                   | 5.54 ms | 1.03      | 1.00      |
   | alternating fill + rect               | 3.52 ms | 1.00      | 0.99      |
   | dash toggle + line                    | 1.75 ms | 1.27      | 1.00      |
   | typical sketch frame (300 shapes)     | 55 µs   | 1.37      | 1.01      |
   | 20,000 style setter calls             | 0.12 ms | 0.98      | 1.01      |
   | direct context writes + rect          | 0.65 ms | 1.00      | 1.01      |
   | 8 canvases, 800 shapes each           | 0.52 ms | 1.24      | 1.01      |
   | `save`/`restore` per shape            | 2.26 ms | 1.26      | 1.06      |
   | `save`/`restore`, style change inside | 2.30 ms | 1.00      | 1.02–1.09 |

   The `save`/`restore` rows are the bug itself: 1.0.2 skips the write after
   `restore()` and draws the wrong color. The remaining cost is the wrapped
   `save()`/`restore()` calls and the snapshot. Copying the snapshot only when
   a style changes within the block measured within noise of this, so the
   simpler eager snapshot stays.

   skia-canvas (pts-render), each build in its own process, medians: style
   calls 0.83×, mixed shapes with drawing 0.93×, one style per shape with
   drawing 1.00×. A `save`/`restore` around every shape is 1.16×, because
   each restore really does revert the color and skia-canvas writes are costly;
   1.0.2 skipped those writes and drew the wrong color. SVG, long single-scene
   runs: fills and polygons 0.90×, opaque strokes 0.69×, translucent strokes
   0.85×, squares 0.95×, mixed styles 0.98×, all within 1% of the first fix.
   node-canvas 3 draws direct writes and restored styles correctly (1.0.2
   does not) at the same speed.

2. **Path sweep** (`661acc7`). `sweep` is 1.0.2's x-order scan again,
   unchanged. When at least one in eight of 64 sampled edges has a window over
   256 candidates, and a block search over them skips at least half their
   blocks, the phase runs `searchSweep`. That function searches long windows
   through a tree over 16-edge blocks in x order, and falls back to scanning
   if its first 32 searches skip too little. Pairs are visited in 1.0.2's
   order. Outputs match 1.0.2 byte for byte on 314 unions, intersections,
   subtractions and xors, and the fuzzer passes on four seeds.

   | `Path.unite`                  | new / 1.0.2 | head / 1.0.2 |
   | ----------------------------- | ----------- | ------------ |
   | 2000 full-width bars          | 0.15        | 0.17         |
   | 2000 full-width bars shuffled | 1.00        | 0.07         |
   | 4000 tall bars, jittered      | 1.01        | 8.6          |
   | 3000 random small squares     | 1.01        | 1.55         |
   | one 20,000-gon                | 1.00        | 1.42         |
   | two small polygons            | 0.99        | 1.26         |

   Shuffled full-width bars are as fast as 1.0.2 but no faster. Head's y-ordered
   tree sped that layout up only by making others quadratic. A merge-sort tree
   could serve both, at about 16 bytes per edge per tree level. The benchmark
   suite now includes the shuffled and tall-bar layouts.

3. **Lost press** (`ea29b7f`). Unbinding mouse or touch input releases its
   press and drops tracked draggers. A down from the pressing contact again, or
   a new first contact of the same kind (a primary pointer of the same
   `pointerType`, or a touchstart whose touches are all new), replaces a stale
   press. A palm touch therefore cannot take a pen press, and a second finger
   still cannot take the first one's. react-pts-canvas's probe now recovers
   after its touch toggle.

4. **Microphone** (`d96d1bb`). `_afterFade` finishes immediately when the
   context is not running, so the tracks end at once and no timer polls. A
   Chromium fake microphone reads `"ended"` right after `stop()`.
   `Sound.reset()` also tolerates Safari's `InvalidStateError` from stopping an
   ended source.

5. **SVG batching** (`3a62679`). A shape joins the previous same-styled run
   when the pixels cannot change: shapes with one opaque paint (fills only when
   their subpaths are circles, rectangles or convex polygons winding the same
   way, which cannot cancel under nonzero), or shapes whose bounds, grown by
   the stroke's reach plus a pixel, miss each of the run's first 32 shapes.
   Classed shapes stay separate. Shape geometry is recorded as flat coordinates
   and evaluated only when a merge needs it, and style runs are compared
   without allocating key arrays.

   | Chromium, 20,000 shapes | 1.0.2  | head    | new    |
   | ----------------------- | ------ | ------- | ------ |
   | filled circles          | 8.0 ms | 28.0 ms | 7.5 ms |
   | squares                 | 3.9 ms | 22.8 ms | 3.8 ms |
   | fill + stroke circles   | 12.7   | 33.1    | 11.9   |
   | opaque strokes          | 6.4    | 27.9    | 5.6    |
   | convex polygons         | 8.2    | 32.8    | 7.9    |
   | translucent strokes     | 6.4    | 28.0    | 7.5    |

   Overlapping translucent strokes are the one cost that remains. They must be
   separate elements to blend like canvas, so this scene emits 609 elements
   instead of 3. At 2000 shapes it is at parity.

6. **Exact predicates** (`15ca003`, `bd368e2`). `Line.intersectLine2D` runs
   its exact collinearity test only when the cross product is within 1e-12 of
   its first term. Exactly collinear inputs always are, since rounding moves
   the cross product by a few ulps of that term. It then computes the ray
   intersection inline. `convexHull` checks sortedness and duplicates in one
   pass, compacts in place, and inlines the floating-point orientation filter.
   `Op` imports a filter-plus-BigInt `orient2dFiltered`, so bundles skip the
   triangulation's integer limb tier. Same-build comparison: intersection
   0.99×, hull 1.02×.

7. **Resize repaint** (`8bf7def`). A stopped CanvasSpace redraws through
   `_repaint()`: players animate once at the last frame's time with no elapsed
   time, without `play()`. The canvas is repainted with no time-0 frame, no
   Tempo beat, and no `onAction` under react-pts-canvas `play={false}` (0 of 30
   moves, against 29 for head).

### Regressions found during the fix pass

- **`a370ccd`, `Pt` constructor.** The buffer check ran before every
  construction and added a second `super()` call. `$add` was 1.4× in Node, and
  in Chromium `Pt` construction rose from 8% to 39% of a polygon-drawing
  profile. The check now sits in the final branch through a helper: parity.
- **`8039da7`, `Color.hex`.** It was 1.65× from `Num.clamp`. Floor, then clamp
  only out-of-range values: parity.
- **`9dd1d9c`, HSL/HSB → RGB.** Rounding three channels cost 4–7%. Indexed
  reads instead of typed-array destructuring and no per-call arrays or
  closures: HSL 0.99×, HSB 0.89×.

### Kept as reviewed

- Voronoi deduplication stays exact. It reads each vertex's coordinates, about
  4% of cell assembly and about 1% with the triangulation.
- Tempo counts and the other behavior changes stay. The changelog now lists
  them under "Behavior changes", with the `count >= n` advice. They argue for
  1.1.0.

### Size

`pts.min.js` is 186.4 KB in 1.0.2, 193.2 KB in head and 201.8 KB now (gzip
59.5, 61.6 and 64.5 KB). The CanvasSpace Vite bundle is 86.3 KB (head 84.5 KB).
Most of the growth over head is the exact SVG merge rule (about 4.6 KB
minified), the sweep block search (1.4 KB) and context observation (1.2 KB). A
write-through cache for SVG, without its accessors, saved 1 KB but made
translucent strokes 13% slower, so it was not used. Budgets in
`check-artifacts.mjs` and `check-package.mjs` sit 2% above this build.
